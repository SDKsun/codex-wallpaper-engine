# GPT 动态壁纸

从 GitHub 源码安装时，请先按[项目构建说明](../../docs/BUILDING.md)生成完整插件；源码不提交管理器二进制或第三方角色素材。下面的使用步骤适用于完成构建并导入的插件。

在当前聊天调用 wallpaper 技能，或输入“打开可视化壁纸库”。

1. 默认打开原版 DSH 六页签，自动读取本机 Wallpaper Engine 壁纸库。在“壁纸库”点击“选择壁纸”，按名称、类型和内容分级筛选。
2. 选择壁纸后即时保存；场景作者属性、播放、轮播、玻璃、字体和预设使用原版控件。
3. 首次使用通过“启用引擎 / 恢复外观”打开原生管理器，再点击“启动 / 重新应用”并确认重启。
4. 原生管理器用于启用和恢复；完整壁纸选择与外观设置在六页签中操作。基础图片 / 视频目录界面仍可从 `/basic` 打开。

设置入口位于顶部挂件内：点击挂件展开壁纸库，再点面板底部的“壁纸引擎设置”。右键挂件可直接打开完整设置，`Ctrl+Alt+W` 快捷键保留。挂件原有移动、拉绳和壁纸库交互保持；右上角不再显示独立设置按钮。

管理页在 Codex 浏览器面板运行，本地服务只监听 127.0.0.1，使用每次启动生成的访问密钥。未应用场景时约两小时后关闭；应用场景后服务继续提供背景资源。再次打开会恢复已选择的本机场景。
完整模式按原版 DSH 规则保存筛选、轮播列表与设置。基础工具的目录轮播间隔至少 30 秒，轮播包含目录中的受支持文件；暂停会停止该目录轮播，恢复不会自动重新开启。

页面的玻璃预览不是聊天背景的生效证明；只有真实聊天界面可确认渲染效果。引擎启用仍由原生管理器处理，本插件不会静默重启当前应用。

完整模式复用固定版本的 [DSH Wallpaper Engine](https://github.com/elysia395/dsh-wallpaper-engine) 宿主模块和原版六页签界面。Codex 适配通过本机服务和限定路径的资源通道连接原界面，保留上游 MIT 许可与素材署名。
原生背景使用私有 Runtime 通信连接原版客户端，图片和视频转为受限的本地 Blob，Scene 使用随包固定的 WebWallGL 3.0.0 与原版渲染控制器。输入框使用单层玻璃，去掉后方独立的纯色遮挡，并继续响应原版外观参数。鼠标由上游被动转发，不拦截聊天点击；互动效果取决于壁纸本身。完整设置存于本地 GPTWallpaper/dsh/config.json，旧 Scene 选择仍有兼容记录。完整模式的播放控件直接控制上游运行时；基础工具暂停会卸载背景，恢复时重新开始。
当前已在 Codex 26.1021.3705.0 的真实窗口验收持续 Scene 渲染和 3840×2160 视频播放；原版鼠标粒子与轨迹在独立严格策略窗口完成验证。管理页面的本地 Web 预览与原生聊天背景是不同的运行环境：原生 Web 和依赖动态 SceneScript 的场景仍有兼容限制，不能把管理页面的成功预览当作原生支持证明。
可直接在聊天说“列出 Wallpaper Engine 壁纸”或“换成星空”，技能使用 list_wallpaper_engine / use_scene 切换。
基础模式的“退出场景壁纸”可回到原来的图片/视频背景。Windows 系统频谱与 Now Playing 使用独立缓存中经过固定 SHA256 校验的原版媒体桥；有效静音频谱与服务不可用会分别报告。原版 DSH 官方桌宠同页联动与画布终端字体接口在 Codex 中没有对应服务，不能把内置吉祥物显示称为官方桌宠联动。
壁纸工具连接时会恢复已启用的场景服务。Windows 启动器使用独立进程代理，并在代码执行前验证它不属于调用方的作业组，避免 Codex 重启时一起退出；当前不自动注册系统启动项。

商店版 Codex 与独立进程统一使用用户目录下 `.codex/wallpaper-local` 保存状态，避免 AppData 虚拟化造成两边读取不同配置。显式隔离数据目录仍可覆盖。实际聊天界面适配需要启用背景引擎并通过真实窗口验收；设置界面加载、测试画布出帧或保存成功均不代表聊天背景已经显示。
