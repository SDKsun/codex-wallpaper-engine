# 兼容范围与验证记录

**当前架构是 MCP 控制插件 + 外部窗口适配器。可选常驻助手在官方入口打开新的普通窗口后自动重新接入，可能短暂重开窗口；它需要单独启用，不属于宿主原生主题扩展。**

截至 2026-10-29，已在 Codex 26.1021.3705.0 验证受管会话关闭最后窗口后的重开，以及完整退出后台后从原官方应用入口重开。常驻助手完成自动接管，新浏览器窗口可见，3840×2160 视频持续出帧，挂件、玻璃边框和反光生效，壁纸配置与本次测试前备份逐字节一致。该结果不代表所有启动参数、客户端版本或 Windows 重启场景均已验证。

2026-11-03 回归发现启动中的子进程变化、辅助窗口、隐藏状态恢复及诊断输出混入 JSON 等问题。本轮修复已在真实会话验证：恢复可见页面，壁纸覆盖 976×810 视口，Scene 约 30 FPS 且画布像素持续变化；受管与普通进程身份保留，壁纸配置和应用配置逐字节不变，启动进程自然退出。以下历史冷启动记录保留；本轮完整退出后的新启动路径仍待单独验收。

2026-11-05 的双窗口修复增加已有受管会话的直接交接：先验证并恢复准确的已有主窗口，再处理新打开的普通实例；随后只修复并验证该受管实例的壁纸资源与注入器，身份消失时停止，不新建浏览器。助手禁用时仍保留普通启动行为，升级保留禁用与暂停决定。该交接和慢预热诊断需区分测试夹具与实际应用验收，不能沿用历史结果视为本轮已通过。

本机已完成新版限定已有实例修复的真实验证：修复进程自然退出 0，保留原浏览器及两个应用进程身份；3840×2160 视频 readyState 4，解码帧从 5462 增至 5565，壁纸覆盖当前 480×600 视口，挂件可见，壁纸与应用配置逐字节不变。该记录证明修复流程没有新增应用，不代表新版助手已经完成原图标交接或完整退出重开。

| 主窗口唤起 | 从受管浏览器的同类窗口中排除工具窗口及空标题辅助窗口；恢复唯一主窗口，隐藏主窗口无需再次启动；多个主窗口仍按歧义拒绝 |
| 已知客户端启动路径 | 对准确匹配的 Store 构建 26.1021.3705.0 验证身份后直接启动，避免已确认的参数丢失与普通实例晚到；其他构建保留原激活策略 |
| 隐藏页恢复 | 系统窗口恢复后若严格验证仍报告隐藏，只正常重新激活同一受管配置一次，再继续真实渲染验证 |
| 中断事务恢复 | 只在受管会话身份前后相同、当前受管配置与已应用快照及标记完全一致时提交事务日志；配置不改写，冲突保留 |
| 自动启动失败 | 后台模式无阻塞式错误弹窗；本次失败保留日志并继续等待后续正常启动；超时及连续检查错误仍有暂停保护 |
| 原生主题插件加载 | 当前加载器不提供宿主 CSS/前端主题资源；同版本插件读取测试明确忽略这些字段 |
| 受管会话最后窗口重开 | 已验证浏览器进程仍存活时重新打开窗口并恢复外观；不等同于完整退出后重新启动 |
| 完整退出后台后再打开 | 已确认旧应用进程数归零，再由原官方 AppsFolder 入口启动；助手接管后在新浏览器身份下恢复实际视频播放、挂件和玻璃效果 |
| 助手控制与卸载 | 暂停、恢复、卸载还原登录启动项、阻止卸载后初始化复活及重新安装均已实测；保留原普通会话及壁纸配置 |
| Windows Codex 背景接入 | 已在 26.1021.3705.0 受管真实窗口验证；不保证其他版本 DOM 与启动协议兼容 |
| 多窗口启动 | 按已验证的调试端口、进程、配置目录及窗口句柄恢复原壁纸窗口；真实双实例恢复后通过可见性与播放验证，保留另一实例及原配置 |
| 新普通启动复用 | 助手启用时，已有准确受管会话先恢复其主窗口，再只接管 15 秒内的新普通实例；复用路径不等待资源预热、不新建浏览器；已有普通会话及多受管实例歧义保留 |

| 视频 | 真实窗口 3840×2160、readyState 4 和播放进度推进已验证 |

| 图片与设置 | 使用原版图片、筛选、预设、轮播、字体与玻璃控件；输入框、外层和页脚背景分别适配 |
| 原生壁纸贴合 | 原生窗口的普通取景至少铺满视口，平移限制在放大后的裁切范围；不改写保存的取景值，保留原视差逻辑；已覆盖 100%/150% 缩放及窗口尺寸变化 |
| 非聊天页面玻璃 | 资料空间/站点、定时任务、插件/技能和菜单采用独立底色；标题伪元素、整页容器与卡片分别处理。浅/深色、主按钮颜色和页面切换清理由独立浏览器夹具验证，不能代替每个页面的真实窗口验收 |
| 聊天项目信息卡 | 真实窗口已确认外框玻璃生效，三处标题及上沿伪元素透明；原生、关闭和全透明策略在独立窗口验证，保留分隔线、布局与滚动尺寸 |
| Web | 管理页面可预览本地 Web；原生聊天中仍有脚本及资源兼容限制 |
| 动态 SceneScript | Codex 的脚本策略限制部分运行时编译；不是所有场景脚本都可用 |
| 系统媒体 | 独立且固定摘要的原版辅助程序；可用性取决于系统提供者及实际播放器 |
| 官方 DSH 桌宠 | 缺少同页公开服务时不可用；内置吉祥物不能作为官方联动已接通的证明 |
| 终端画布字体 | Codex 无对应公开服务，不能承诺原版 DSH 的全部终端字体设置 |
| macOS / Linux | 当前插件未验证；Windows 源码构建与管理器不能据此视为跨平台支持 |

成功判定要求实际原生渲染。选择 Scene 时必须存在真实渲染控制器、有效画布和持续 FPS；海报回退不会被标记为 Scene 成功。视频需要真实解码尺寸和可播放状态。管理页面样式、配置保存及测试夹具都不单独作为原生验收依据。

不修改官方应用安装目录、签名或 CSP。不同客户端和不同壁纸的兼容性需要分别验证。原生 Web 与动态脚本的进一步适配尚未实现，不能把设计方案当作现有功能。
